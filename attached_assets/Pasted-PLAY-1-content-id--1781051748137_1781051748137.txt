PLAY강릉 강릉노트 및 관리자 편집 기능의 다음 작업 방향을 정리합니다.

현재까지 완료된 전제:

1. 카드 클릭 기본 경로는 `/content/:id` 강릉노트로 변경됨
2. 원본 보기는 별도 버튼으로 분리됨
3. link URL이 있으면 sourceType이 manual이어도 원본 보기 버튼이 표시됨
4. 강릉노트 `/content/:id`는 SEO형 보기 페이지로 1차 개선됨
5. 관리자 이벤트 편집 페이지에서 link, source, hashtags, extraImages 편집 기능이 추가됨
6. 카드 이미지 재생성 버튼이 추가됨
7. TypeScript 체크와 validate.sh는 통과한 상태

이번 작업의 방향:

강릉노트는 복잡한 지도 기능보다, 사용자가 바로 이해할 수 있는 “장소/주소 텍스트” 중심으로 운영합니다.
또한 예약/신청 URL은 모든 콘텐츠에 필수로 넣는 것이 아니라, 실제 예약·신청·예매·문의 행동이 필요한 콘텐츠에만 선택적으로 사용하는 구조로 설계합니다.

1. 장소/주소 표시 원칙

현재 `location` 필드를 강릉노트의 “장소/주소” 정보로 사용합니다.

관리자 편집 화면과 강릉노트 화면에서 location의 의미를 더 명확히 보여 주세요.

권장 표시:

* 관리자 편집 화면 라벨: `장소/주소`
* 강릉노트 핵심 정보 카드 라벨: `장소/주소`
* 예시 placeholder: `예: 강릉시 남대천 행사장 일대 / 강원특별자치도 강릉시 ○○로 ○○`

구현 원칙:

* location은 사용자가 복사하거나 외부 지도 앱에서 검색하기 쉬운 텍스트로 표시합니다.
* 지도 API 연동은 이번 작업 범위에 넣지 않습니다.
* 지도 iframe 삽입도 이번 작업 범위에 넣지 않습니다.
* 자동 지도 링크 생성도 이번 작업 범위에 넣지 않습니다.
* 현재는 장소/주소 텍스트를 정확히 입력하고 표시하는 데 집중합니다.

2. 예약/신청 URL 설계 원칙

예약/신청 URL은 모든 강릉노트에 필요한 필드가 아닙니다.

다음 유형의 콘텐츠에서만 필요합니다.

* 체험 신청
* 공연 예매
* 교육 접수
* 행사 참가 신청
* 광고주 예약 페이지
* 스마트스토어
* 네이버예약
* 인스타그램 DM 또는 문의 링크
* 기타 사용자의 직접 행동이 필요한 링크

기본 원칙:

* 원본 URL과 예약/신청 URL은 목적이 다릅니다.
* 원본 URL은 출처 확인용입니다.
* 예약/신청 URL은 사용자 행동 유도용입니다.
* reservationUrl은 값이 있을 때만 “예약/신청하기” 버튼으로 표시하는 선택 필드여야 합니다.
* reservationUrl이 없으면 버튼을 표시하지 않습니다.

다만 reservationUrl은 현재 DB에 없는 필드이므로, 이번 단계에서는 DB schema를 변경하지 말고 설계만 정리해 주세요.

이번 단계에서는 기존 link 필드를 계속 원본 보기 용도로 사용합니다.

3. 강릉노트 CTA 버튼 구조

현재 단계의 버튼 구조는 다음을 유지합니다.

* 원본 보기
* 공유하기
* PLAY강릉 홈

원본 보기 버튼:

* link 값이 있으면 표시합니다.
* sourceType이 manual이어도 link 값이 있으면 표시합니다.
* 새 탭으로 열리게 유지합니다.
* `target="_blank"`와 `rel="noopener noreferrer"`를 유지합니다.

예약/신청하기 버튼:

* 이번 단계에서는 구현하지 않습니다.
* 추후 reservationUrl 필드가 생기면 값이 있을 때만 표시하는 방식으로 확장합니다.

4. 관리자 편집 화면 보완

현재 관리자 이벤트 편집 페이지에서 location 필드가 있다면, 라벨과 안내 문구를 “장소/주소” 중심으로 바꿔 주세요.

확인할 것:

* 새 피드 등록 화면에서도 location 라벨이 “장소/주소”로 이해되도록 되어 있는지
* 기존 이벤트 수정 화면에서도 location 라벨이 “장소/주소”로 이해되도록 되어 있는지
* 강릉노트 핵심 정보 카드에서도 location이 “장소/주소”로 표시되는지

5. 추천 포인트 섹션 처리

현재 강릉노트에 표시되는 “PLAY강릉 추천 포인트” 섹션은 사용성이 낮으므로 제거합니다.

이 섹션은 별도 검증된 정보 필드가 아니라 socialDraft.caption, category, location 등을 조합한 일반 문구일 수 있으므로, 지금 단계에서는 사용하지 않습니다.

강릉노트 구조는 다음 중심으로 정리해 주세요.

* 대표 이미지
* 카테고리
* 제목 H1
* 한 줄 요약
* 핵심 정보 카드
* 상세 내용
* 추가 이미지
* 동영상
* 해시태그
* 원본 보기
* 공유하기
* PLAY강릉 홈
* 관련 강릉노트

H2 구조에서도 “추천 포인트” H2는 제거해 주세요.

권장 H2 구조:

* 핵심 정보
* 상세 내용
* 추가 이미지 또는 영상
* 관련 강릉노트

단, 추가 이미지나 영상이 없으면 해당 H2 섹션은 표시하지 않아도 됩니다.

6. SEO 구조 유지

추천 포인트 섹션을 제거하더라도 SEO 기본 구조는 유지해 주세요.

유지할 항목:

* 고유 title 태그
* meta description
* canonical URL
* H1은 1개
* H2 구조
* OG 태그
* JSON-LD
* 이미지 alt 텍스트
* 날짜, 장소/주소, 카테고리, 출처, 문의 정보의 HTML 텍스트 표시
* 관련 강릉노트 내부 링크

중요:

* 이미지 안의 문구만으로 정보를 전달하지 말고, 중요한 내용은 HTML 텍스트로도 표시해 주세요.
* 화면 H1은 원본 title을 유지합니다.
* SEO title에서만 필요한 경우 지역 키워드를 보강합니다.
* title, location, source 중 하나라도 “강릉”이 있으면 “강릉” prefix를 중복으로 붙이지 않습니다.

작업 후 다음을 확인해 주세요.

1. TypeScript 체크 통과

3. 관리자 편집 화면에서 location 라벨이 “장소/주소” 의미로 표시되는지 확인

5. “PLAY강릉 추천 포인트” 섹션이 제거되었는지 확인
6. H2 구조에서 추천 포인트 H2가 제거되었는지 확인

이번 작업의 목표:

강릉노트를 복잡한 기능 페이지로 만들기보다, 정확한 장소/주소 텍스트와 출처, 상세 정보, 이미지, 영상, 해시태그, 관련 콘텐츠가 잘 정리된 SEO형 로컬 정보 페이지로 안정화하는 것입니다.
