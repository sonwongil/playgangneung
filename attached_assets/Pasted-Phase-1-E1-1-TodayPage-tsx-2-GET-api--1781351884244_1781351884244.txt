# Phase 1-E2 승인 범위

## daily_top5 저장 기능

이번 단계의 목표는 `/admin/v2/today` 화면에서 local state로 선택한 1~5개 슬롯을 기존 `daily_top5` 저장 API에 저장하는 것입니다.

이번 단계는 “홈 리빌딩”이 아닙니다.
이번 단계는 “SNS 발행”이 아닙니다.
이번 단계는 “Meta 광고 확장”이 아닙니다.
이번 단계는 “공개 전환”이 아닙니다.

오직 **오늘의 강릉소식 1~5개 저장**까지만 구현합니다.

---

## 1. 허용 작업

다음 작업만 허용합니다.

1. `/admin/v2/today`의 저장 버튼 활성화
2. 선택된 슬롯 1~5개를 기존 `daily_top5` 저장 API로 저장
3. 기존 API가 있다면 그 API만 사용
4. 새 API가 꼭 필요하면 구현하지 말고 먼저 보고
5. 저장 성공 시 toast 또는 안내 배너 표시
6. 저장 후 다시 `GET /api/top5?date=YYYY-MM-DD`로 읽어와 화면 확인
7. 저장할 때 슬롯 순서를 유지
8. 저장할 때 빈 슬롯은 제외하거나 null 처리 방식 중 기존 API 구조에 맞춰 적용
9. typecheck 실행
10. build 실행

---

## 2. 저장 데이터 원칙

저장 대상은 `daily_top5`입니다.

저장 구조는 기존 API 구조를 먼저 확인하고 따르세요.

예상 구조는 다음과 같습니다.

```text
date: YYYY-MM-DD
items: [
  { eventId: "...", rank: 1 },
  { eventId: "...", rank: 2 },
  { eventId: "...", rank: 3 },
  { eventId: "...", rank: 4 },
  { eventId: "...", rank: 5 }
]
```

단, 실제 기존 API가 다른 구조를 쓰고 있다면 기존 구조를 우선합니다.

중요:

1. event 자체의 status를 변경하지 말 것
2. events 테이블을 수정하지 말 것
3. contentBlocks를 수정하지 말 것
4. 홈 화면 코드를 수정하지 말 것
5. SNS 발행 상태를 수정하지 말 것

## 4. 저장 버튼 동작

저장 버튼은 다음 순서로 동작해야 합니다.

1. 현재 선택된 슬롯 확인
2. 선택 항목이 0개이면 저장 막기
3. 선택 항목이 5개 초과이면 저장 막기
4. 선택된 항목의 id와 순번을 정리
5. 기존 daily_top5 저장 API 호출
6. 성공 시 안내 표시
7. 다시 조회해서 화면 갱신
