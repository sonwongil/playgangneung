# Phase 1-E1 승인 범위

## 오늘의 강릉소식 선정 화면 — 저장 없는 미리보기

이번 단계의 목표는 `/admin/v2/today` 화면에서 강릉노트 후보를 보고,
오늘의 강릉소식 5개를 어떻게 선정할지 **화면 구조만 만드는 것**입니다.

이번 단계는 “저장”이 아닙니다.
이번 단계는 `daily_top5` 수정이 아닙니다.
이번 단계는 홈 노출 반영이 아닙니다.
이번 단계는 SNS 발행이 아닙니다.

오직 **오늘의 강릉소식 선정 UI 미리보기**까지만 구현합니다.

## 3. 화면 구성

`/admin/v2/today` 화면은 다음 구조로 만드세요.

### 상단

1. 페이지 제목: 오늘의 강릉소식
2. 설명 문구: 강릉노트 중 오늘 홈 상단에 노출할 5개 콘텐츠를 선정하는 화면입니다.
3. 날짜 선택 영역

   * 기본값: 오늘 날짜
   * 이번 단계에서는 local state만 사용
   * 날짜 변경 시 DB 요청 또는 저장 금지

### 현재 선정 슬롯

1. 1번 슬롯
2. 2번 슬롯
3. 3번 슬롯
4. 4번 슬롯
5. 5번 슬롯

각 슬롯 표시 항목:

1. 순번
2. 썸네일
3. 제목
4. 카테고리
5. 출처
6. 제거 버튼

이번 단계의 제거 버튼은 local state에서만 제거합니다.

### 후보 목록

기존 `GET /api/events` 데이터를 사용해 후보 목록을 표시합니다.

후보 목록 컬럼:

1. 썸네일
2. 제목
3. 카테고리
4. 상태
5. 본문 여부
6. 출처
7. 수정일
8. 선택 버튼

선택 버튼은 local state에만 반영합니다.

## 4. 후보 필터 기준

이번 단계에서는 DB 구조를 바꾸지 않기 위해 단순 기준으로 갑니다.

추천 기준:

```text
GET /api/events 결과 중 title이 있고,
status가 deleted/excluded가 아닌 항목을 후보로 표시한다.
```

contentBlocks가 있으면 “본문 있음”으로 표시하고,
없으면 “본문 없음”으로 표시합니다.

과도한 필터링은 아직 하지 마세요.
