PLAY강릉 메인 UI 구조를 카테고리 중심 구조에서 “실시간 피드 + 해시태그 기반 구조”로 전면 개편해주세요.

핵심 방향:
PLAY강릉은 일반 홈페이지가 아니라
“강릉의 실시간 흐름 피드” 방향으로 전환합니다.

현재 상단 카테고리(전체/행사/맛집/정보/스토리/영상)는 사용자가 한 번 더 탐색해야 하는 구조라 흐름이 끊깁니다.

따라서:
- 모든 콘텐츠는 기본적으로 메인 피드에 통합 노출
- 카테고리는 해시태그 기반 필터 방식으로 변경
- 페이지 이동 없이 즉시 필터링
- 인스타/Threads/TikTok 느낌의 UX로 변경

5. 매우 중요: #오늘의행사 처리 방식
━━━━━━━━━━━━━━━

핵심 요구사항:

사용자가 직접 #오늘의행사를 붙일 수 있으므로
태그만 보고 노출하면 안 됨.

반드시 날짜를 함께 검사해야 함.

즉:
#오늘의행사 필터는
hashtags 배열만으로 판단 금지.

조건:
1. hashtags에 "#오늘의행사" 포함
2. 현재 날짜 >= startDate
3. 현재 날짜 <= endDate
4. endDate 없으면 startDate 기준 하루 처리

즉:
지난 행사인데 #오늘의행사가 붙어있으면
필터에서 자동 제외.

구현 예시:

function isTodayEvent(event) {
  const today = new Date();
  const start = new Date(event.startDate);
  const end = event.endDate ? new Date(event.endDate) : start;

  today.setHours(0,0,0,0);
  start.setHours(0,0,0,0);
  end.setHours(23,59,59,999);

  return today >= start && today <= end;
}

filter:
event.hashtags.includes("#오늘의행사")
&& isTodayEvent(event)

중요:
#오늘의행사 = 단순 문자열이 아니라
“날짜 조건 기반 동적 필터”.

10. 매우 중요: 기존 기능 깨짐 방지
━━━━━━━━━━━━━━━

현재 가장 중요한 문제는:
새 기능 추가 시 기존 기능이 자주 깨지는 점.

따라서:
“기능 추가 전용 개발”
이 아니라
“회귀 검증 기반 개발”로 변경 필요.

현재 구축된 검증 시스템 유지:

scripts/validate.sh

검사 항목:
- /api/feed 정상 응답
- /api/events 정상 응답
- status API 정상
- bulk delete 정상
- proxy download 예외 처리
- Cache-Control 헤더
- TypeScript 오류

앞으로 규칙:
1. 코드 수정
2. validate.sh 실행
3. 실패 시 배포 금지
4. 통과 후만 완료 처리

추가 요청:
해시태그 필터 추가 후에도
기존 피드 API와 상세 페이지가 절대 깨지지 않도록 검증 추가.
