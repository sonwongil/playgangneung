강릉노트 편집 구조를 “원본 링크 자동 추출 → BlockNote 본문 자동 생성 → 관리자가 수정” 방식으로 개선해 주세요.

현재 문제:

* `/admin/events/:id` 편집 화면에 제목, 장소, 문의, 출처, 원본 링크, 대표 이미지, 상세 설명 등 입력칸이 너무 많습니다.
* BlockNote가 도입되었으므로, 장소/문의/상세설명/출처/이미지/링크 등은 본문 안에서 자유롭게 구성할 수 있습니다.
* 관리자는 원본 링크에서 자동 추출된 내용을 바탕으로 BlockNote 본문을 수정하는 방식이 더 적합합니다.

목표:

1. 원본 링크를 입력하고 “자동 추출”을 누르면 기존 추출 API를 사용해 제목, 설명, 이미지, 날짜, 장소, 문의처, 출처 등을 가져옵니다.
2. 가져온 정보를 기존 개별 입력칸에만 넣지 말고, BlockNote 본문 기본 초안으로도 자동 생성해 주세요.
3. 관리자는 자동 생성된 BlockNote 본문을 자유롭게 수정할 수 있어야 합니다.
4. 저장 시 `contentBlocks`가 `events.content_blocks`에 저장되어야 합니다.
5. `/content/:id`에서는 `content_blocks`가 있으면 BlockNote 본문을 우선 렌더링하고, 없으면 기존 description fallback을 유지합니다.

BlockNote 자동 초안 구성 예시:

* 제목 블록
* 핵심 정보 섹션

  * 일정
  * 장소
  * 문의
  * 출처
* 소개 섹션

  * 원본에서 추출한 설명 또는 요약
* 방문 전 참고사항 섹션

  * 운영 내용은 변경될 수 있으니 원본을 확인하세요.
* 원본 보기 섹션

  * 원본 링크

관리자 화면 구조:
기본 표시 항목:

* 원본 링크
* 자동 추출 버튼
* 제목
* 카테고리
* 강릉노트 본문 에디터
* 저장 / 공개 버튼

접힘 영역으로 이동할 항목:

* 시작일
* 종료일
* 대표 이미지 URL / 파일 업로드
* 출처 / 업체명
* 해시태그
* 장소/주소
* 문의처

중요:

* 제목과 카테고리는 기본 화면에 남깁니다.
* 대표 이미지는 홈 카드와 SNS 공유에 필요하므로 완전 삭제하지 말고 접힘 영역으로 이동합니다.
* 시작일/종료일은 행사 정렬과 오늘의 행사 필터에 필요하므로 완전 삭제하지 말고 접힘 영역으로 이동합니다.
* 원본 링크는 반드시 유지합니다.
* 기존 개별 필드 값은 삭제하지 말고, 자동 추출 후 메타데이터로 계속 저장합니다.
* BlockNote 본문은 방문자에게 보여지는 주 콘텐츠로 사용합니다.
* 기존 콘텐츠가 깨지면 안 됩니다.

자동 추출 후 동작:

1. 추출된 제목 → 제목 입력칸 반영
2. 추출된 이미지 → 대표 이미지 URL 반영
3. 추출된 설명 → description 반영
4. 추출된 날짜/장소/문의/출처 → 해당 필드 반영
5. 동시에 BlockNote `contentBlocks` 초안 생성
6. 사용자가 이미 BlockNote 본문을 수정한 상태라면, 자동 덮어쓰기 전에 확인 안내 또는 버튼으로 “본문 초안 다시 생성”을 제공해 주세요.

버튼 제안:

* URL 자동 추출
* BlockNote 본문 초안 생성
* 기존 본문 유지
* 추출값으로 본문 다시 만들기

주의:

* 새 피드 등록 화면과 기존 콘텐츠 편집 화면의 구조를 혼동하지 마세요.
* 먼저 `/admin/events/:id` 기존 콘텐츠 편집 화면에 적용해 주세요.
* 그다음 2차로 새 피드 등록 모달에도 같은 구조를 적용할 수 있게 설계해 주세요.
* SNS 관리자 패널 로직은 건드리지 마세요.
* 일반 방문자 HTML에 관리자 문자열이 포함되면 안 됩니다.
* PM2, nginx, ecosystem.config.cjs, DNS, SSL은 건드리지 마세요.
* Cafe24 직접 수정 금지입니다.
* Replit → GitHub → Cafe24 순서 유지하세요.

검증:

1. 원본 링크 자동 추출 후 제목/대표이미지/설명/메타정보가 채워지는지
2. 자동 추출 후 BlockNote 본문 초안이 생성되는지
3. BlockNote 본문을 수정하고 저장할 수 있는지
4. 저장 후 `/content/:id`에서 BlockNote 본문이 표시되는지
5. 다시 관리자 화면에 들어가도 BlockNote 본문이 유지되는지
6. contentBlocks가 없는 기존 콘텐츠는 description fallback으로 정상 표시되는지
7. typecheck/build 통과
8. GitHub main 일반 push
