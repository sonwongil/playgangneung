PLAY강릉 강릉노트 구조 개선 작업을 진행합니다.

이번 작업의 목적은 단순 화면 꾸미기가 아닙니다.
`/content/:id` 페이지를 PLAY강릉의 핵심 콘텐츠 자산인 “강릉노트”로 정리하는 것입니다.

강릉노트의 정의:

강릉노트는 블로그형 긴 글이 아닙니다.
또 원본 링크로 보내기 전 거치는 단순 중간 페이지도 아닙니다.

강릉노트는 PLAY강릉 안에 쌓이는 카드형 로컬 정보 상세 페이지입니다.
사용자가 10초 안에 내용을 이해하고, Google 검색과 AI 검색이 페이지 내용을 정확히 읽을 수 있도록 구성된 SEO 최적화 페이지여야 합니다.

즉 강릉노트는 다음 4가지 역할을 동시에 해야 합니다.

1. 사용자에게 빠른 판단을 주는 상세 페이지
2. Google SEO에 최적화된 검색 자산
3. Facebook/Instagram 등 SNS 공유의 랜딩 페이지
4. 향후 유료광고 랜딩 페이지로 확장 가능한 구조

현재까지 완료된 전제:

1. 카드 클릭 기본 경로는 `/content/:id` 강릉노트로 변경됨
2. 원본 보기는 별도 버튼으로 분리됨
3. link URL이 있으면 sourceType이 manual이어도 원본 보기 버튼이 표시되도록 수정됨
4. 카드 접근성은 `role="link"`, `tabIndex`, Enter/Space 키 처리로 보완됨
5. `/viewer`는 삭제하지 않고 유지됨
6. TypeScript 체크와 validate.sh는 통과한 상태

이번 작업 목표:

`/content/:id` 페이지가 단순 링크 중간 페이지처럼 보이지 않고, PLAY강릉의 SEO 최적화 강릉노트로 보이도록 내용 구조와 HTML 구조를 보강해 주세요.

중요 원칙:

1. 없는 정보를 억지로 만들지 마세요.
2. 현재 DB에 존재하는 필드와 기존 데이터만 우선 활용해 주세요.
3. DB schema 변경은 하지 마세요.
4. 화면 디자인보다 먼저 SEO 정보 구조를 정확히 잡아 주세요.
5. 이미지 안의 문구만으로 정보를 전달하지 말고, 중요한 내용은 반드시 HTML 텍스트로도 제공해 주세요.

강릉노트 화면 구성 요구사항:

1. 대표 이미지 영역

* `public/cards/{id}.png` 카드 이미지가 있으면 대표 이미지로 우선 표시해 주세요.
* 카드 이미지가 없고 `thumbnail`이 있으면 thumbnail을 표시해 주세요.
* 둘 다 없으면 카테고리 기반 배경 또는 텍스트 히어로를 표시해 주세요.
* 모든 이미지에는 의미 있는 alt 텍스트를 넣어 주세요.
* alt 예시: “강릉 가족 체험 프로그램 안내 이미지”

2. 제목 영역

* 콘텐츠 제목은 H1으로 표시해 주세요.
* H1은 페이지당 하나만 사용해 주세요.
* 제목에는 가능하면 강릉, 행사명, 장소명, 핵심 주제가 자연스럽게 드러나야 합니다.
* 억지로 제목을 새로 만들지는 말고 기존 title을 사용하되, 표시 구조를 명확히 해 주세요.

3. 한 줄 요약 영역

* 제목 아래에 한 줄 요약을 명확히 표시해 주세요.
* description의 첫 문장, socialDraft의 요약 문장, 기존 설명 데이터 중 가장 적합한 문장을 활용해 주세요.
* 요약이 없으면 description 일부를 짧게 잘라 사용해도 됩니다.
* 요약은 meta description에도 활용 가능해야 합니다.

4. 핵심 정보 카드

날짜, 장소, 카테고리, 출처, 문의 정보를 카드형 박스로 정리해 주세요.

현재 있는 정보만 표시합니다.

표시 후보:

* 날짜 또는 기간
* 장소
* 카테고리
* 출처 기관
* 문의
* 원본 URL

주의:

* 운영시간, 가격, 예약 URL은 아직 별도 DB 필드가 없으므로 억지로 표시하지 마세요.
* startDate와 endDate가 모두 있고 서로 다르면 기간 형식으로 표시해 주세요.
* 날짜가 하나만 있으면 단일 날짜로 표시해 주세요.

5. “왜 가볼 만한가” 또는 “PLAY강릉 추천 포인트” 영역

이 영역은 강릉노트를 단순 중간 페이지가 아니라 PLAY강릉 자체 콘텐츠로 보이게 만드는 핵심입니다.

* H2 제목으로 “왜 가볼 만한가” 또는 “PLAY강릉 추천 포인트”를 추가해 주세요.
* 기존 description, category, location, socialDraft에서 활용 가능한 문장이 있으면 사용해 주세요.
* recommend_reason DB 필드는 아직 추가하지 마세요.
* 추출할 내용이 충분하지 않으면 짧은 기본 안내 문구를 사용하거나 자연스럽게 영역을 숨겨 주세요.
* 허위 문장이나 실제 데이터에 없는 정보는 만들지 마세요.

추천 포인트 예시 톤:

“강릉 지역 소식 중 가족 단위 방문객에게 도움이 될 만한 정보입니다. 날짜와 장소가 명확해 방문 계획을 세우기 좋습니다. 자세한 조건과 신청 내용은 원본 페이지에서 확인해 주세요.”

단, 실제 콘텐츠 성격에 맞게 너무 과장하지 말고 자연스럽게 표시해 주세요.

6. 상세 내용 영역

* 기존 description 또는 본문 내용을 H2 “상세 내용” 아래에 표시해 주세요.
* 너무 긴 텍스트는 문단을 나눠 읽기 쉽게 정리해 주세요.
* 줄바꿈이 사라져 한 덩어리로 보이지 않게 해 주세요.
* HTML로 표시할 때 XSS 위험이 없도록 escape 처리를 유지해 주세요.

7. 추가 이미지 영역

* extraImages 필드가 있으면 대표 이미지 아래 또는 상세 내용 근처에 표시해 주세요.
* 간단한 가로 스크롤 이미지 목록 또는 슬라이더 형태면 충분합니다.
* 이미지 로드 실패 시 깨진 이미지 아이콘이 보이지 않도록 처리해 주세요.
* 각 이미지에도 alt 텍스트를 넣어 주세요.

8. 해시태그 영역

* hashtags 필드가 있으면 본문 하단에 배지 형태로 표시해 주세요.
* 예: #강릉행사 #가족체험 #주말나들이
* 해시태그는 나중에 검색·필터와 연결될 수 있으므로 구조적으로 분리해 주세요.

9. CTA 버튼 영역

강릉노트 하단 또는 고정 하단 영역에 행동 버튼을 명확히 배치해 주세요.

현재 단계의 기본 버튼:

* 원본 보기
* 공유하기
* PLAY강릉 홈

원본 보기 조건:

* item.link 또는 원본 URL이 있으면 표시
* sourceType이 manual이어도 URL이 있으면 표시
* 새 탭으로 열기
* `target="_blank"`와 `rel="noopener noreferrer"` 유지

예약/신청 버튼:

* 아직 reservationUrl 필드가 없으므로 별도 예약/신청 버튼은 만들지 마세요.
* 단, 현재 원본 URL이 사실상 예약 페이지인 경우에도 임의로 판단하지 말고 “원본 보기”로 표시해 주세요.

10. 관련 강릉노트 영역

하단에 관련 콘텐츠 2~3개를 표시해 주세요.

기준:

* 같은 category 기준 우선
* 현재 콘텐츠 id는 제외
* status가 approved 또는 published인 콘텐츠만 표시
* draft 콘텐츠는 표시하지 않음
* 제목, 카테고리, 날짜 정도만 간단히 표시
* 클릭 시 `/content/:id`로 이동

이 영역은 사용자 체류와 내부 링크 SEO에 중요합니다.

SEO 필수 요구사항:

1. title 태그

각 강릉노트마다 고유한 title 태그를 출력해 주세요.

권장 형식:

`콘텐츠 제목 | PLAY강릉`

또는

`콘텐츠 제목 - 강릉 날짜·장소 정보 | PLAY강릉`

2. meta description

한 줄 요약을 meta description으로 사용해 주세요.

내용이 없으면 description 앞부분을 자연스럽게 잘라 사용해 주세요.

3. canonical URL

각 강릉노트에는 자기 자신의 canonical URL을 넣어 주세요.

예:

`https://playgangneung.com/content/{id}`

외부 원본 URL을 canonical로 쓰면 안 됩니다.
강릉노트는 PLAY강릉 자체 정리 콘텐츠이므로 canonical은 PLAY강릉 URL이어야 합니다.

4. H 태그 구조

* H1: 콘텐츠 제목 1개
* H2: 핵심 정보
* H2: 왜 가볼 만한가 또는 PLAY강릉 추천 포인트
* H2: 상세 내용
* H2: 관련 강릉노트

이 구조를 지켜 주세요.

5. JSON-LD 구조화 데이터

현재 JSON-LD가 있다면 깨지지 않게 유지해 주세요.

가능하면 콘텐츠 유형에 따라 다음 구조를 유지 또는 개선해 주세요.

* 행사, 축제, 공연: Event
* 일반 소식: Article 또는 NewsArticle
* 장소 소개: Place
* 맛집, 상점, 광고주: LocalBusiness 또는 Restaurant
* 광고 랜딩: 추후 LocalBusiness 기반 확장 가능

현재 DB 정보만으로 가능한 범위에서 적용하고, 없는 필드는 억지로 만들지 마세요.

6. OG 태그 유지

SNS 공유를 위해 다음 OG 태그는 유지해 주세요.

* og:title
* og:description
* og:image
* og:url
* og:type

SNS 공유 링크는 계속 `/content/:id`를 기준으로 유지해 주세요.

7. 이미지 SEO

* 대표 이미지와 추가 이미지에는 alt 텍스트를 넣어 주세요.
* 이미지 안의 핵심 문구는 본문 텍스트에도 표시되도록 해 주세요.
* 이미지 파일만으로 정보를 전달하지 마세요.

8. 내부 링크

* 관련 강릉노트 2~3개를 내부 링크로 제공해 주세요.
* 이 내부 링크는 SEO와 사용자 체류에 중요합니다.

9. 모바일 가독성

모바일에서 다음 순서가 자연스럽게 보여야 합니다.

대표 이미지
→ 카테고리
→ 제목
→ 한 줄 요약
→ 핵심 정보
→ 추천 포인트
→ 상세 내용
→ 원본 보기 / 공유하기
→ 관련 강릉노트

기술적 주의사항:

1. DB schema 변경하지 마세요.
2. link_mode, reservation_url, opening_hours, price, recommend_reason, approved_at 필드는 아직 추가하지 마세요.
3. nginx, DNS, SSL, PM2, ecosystem.config.cjs는 건드리지 마세요.
4. `/viewer`는 삭제하지 마세요.
5. 광고 카드 기존 동작은 건드리지 마세요.
6. draft 142건은 일괄 승인하지 마세요.
7. React 라우터가 아니라 Express SSR HTML로 처리되는 현재 `/content/:id` 구조를 유지해 주세요.
8. XSS 방지를 위해 기존 escape 처리 흐름을 유지해 주세요.

검증 요청:

작업 후 다음을 확인해 주세요.

1. TypeScript 체크 통과
2. scripts/validate.sh 통과
3. `/content/:id` 실제 렌더링 확인
4. 모바일 화면 스크린샷 확인
5. 대표 이미지 표시 확인
6. title, meta description, canonical 출력 확인
7. H1/H2 구조 확인
8. OG 태그 유지 확인
9. JSON-LD 유지 확인
10. 원본 보기 버튼 표시 확인
11. sourceType이 manual이어도 link가 있으면 원본 보기 표시 확인
12. 관련 강릉노트가 draft를 제외하고 표시되는지 확인
13. SNS 공유 링크가 `/content/:id` 기준인지 확인

이번 작업의 최종 기준:

`/content/:id` 페이지를 봤을 때 사용자가 “중간 페이지”라고 느끼지 않고,
“PLAY강릉이 정리한 강릉 정보 카드 상세 페이지”라고 느껴야 합니다.

또한 Google과 AI가 이 페이지에서 다음 정보를 HTML 텍스트와 구조화 데이터로 읽을 수 있어야 합니다.

* 무엇에 대한 콘텐츠인지
* 언제 진행되는지
* 어디에서 진행되는지
* 어떤 카테고리인지
* 출처가 어디인지
* 왜 볼 만한지
* 원본 정보는 어디인지
* 관련된 다른 강릉 콘텐츠는 무엇인지
