# Phase 1-D 승인 범위

## 강릉노트 목록 화면 — 읽기 중심 + 편집 이동

이번 단계의 목표는 `/admin/v2/notes`에서 강릉노트로 저장된 콘텐츠를 목록으로 확인하고, 각 항목을 편집 화면으로 이동할 수 있게 하는 것입니다.

이번 단계는 “공개”가 아닙니다.
이번 단계는 “오늘의 강릉소식 선정”이 아닙니다.
이번 단계는 “SNS 발행”이 아닙니다.
이번 단계는 “보류/제외 처리”가 아닙니다.

오직 **강릉노트 목록 확인 + 편집 화면 이동**까지만 구현합니다.

## 2. 목록 표시 기준

우선 1차에서는 별도 스키마 변경 없이 기존 events 데이터를 사용합니다.

표시 기준은 다음 중 가능한 방식으로 하세요.

### 추천 기준

`contentBlocks`가 있거나, description/title/category/source/link가 있는 기존 event를 목록에 표시합니다.

단, 현재 구조상 수집함과 강릉노트가 같은 events 테이블을 쓰고 있으므로, 이번 단계에서는 과도한 필터링을 하지 말고 다음 기준으로 단순하게 갑니다.

```text
GET /api/events 결과 전체를 표시하되,
화면명은 강릉노트 관리로 두고,
contentBlocks 유무와 status를 명확히 표시한다.
```

이유:

1. 아직 별도 note_type 필드가 없음
2. DB 변경 없이 진행해야 함
3. 수집함과 강릉노트 분리 기준은 다음 단계에서 설계하는 것이 안전함

## 5. 편집 화면 연결

편집 버튼은 다음 중 현재 구조에 맞는 방식으로 연결하세요.

### 1안

```text
/admin/v2/notes/new?sourceId={id}
```

현재 구현된 NewNotePage를 재사용합니다.

### 2안

```text
/admin/v2/notes/{id}
```

기존 NoteEditPage stub를 실제 편집 화면으로 연결합니다.

추천은 1차에서는 1안입니다.
이유는 이미 NewNotePage가 GET/PATCH 저장 구조를 갖고 있기 때문입니다.

단, 화면 제목은 sourceId가 있어도 “강릉노트 편집”으로 표시할 수 있습니다.
