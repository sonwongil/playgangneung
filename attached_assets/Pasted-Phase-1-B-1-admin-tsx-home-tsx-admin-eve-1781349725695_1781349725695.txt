# Phase 1-C1 승인 범위

## 강릉노트 전환 준비 화면 / 저장 없는 미리보기 단계

이번 단계의 목표는 수집함 항목을 실제로 DB에 저장하거나 상태 변경하지 않고,
“강릉노트로 전환하면 어떤 화면과 데이터가 만들어지는지”를 확인하는 것입니다.

## 허용 작업

1. `/admin/v2/inbox`의 “강릉노트로 전환” 버튼만 활성화
2. 버튼 클릭 시 DB 변경 없이 `/admin/v2/notes/new?sourceId=...` 또는 유사 경로로 이동
3. `/admin/v2/notes/new` 신규 화면 생성
4. 기존 `GET /api/events` 또는 `GET /api/events/:id`를 읽기 전용으로 사용
5. 선택한 수집 항목의 데이터를 강릉노트 초안 형태로 화면에 표시
6. 제목, 요약, 카테고리, 원본 URL, 대표 이미지, 출처, 날짜, 본문 초안 미리보기 표시
7. 저장 버튼은 disabled 또는 “다음 단계에서 구현” placeholder 처리
8. BlockNote 실제 저장 기능은 아직 구현하지 않음
9. typecheck 실행
10. build 실행

## 화면 구성

`/admin/v2/notes/new?sourceId=...` 화면은 다음 구조로 만드세요.

1. 상단 제목: 강릉노트 전환 미리보기
2. 안내 문구: 이 화면은 수집함 항목을 강릉노트 초안으로 전환하기 전 미리보기입니다.
3. 원본 정보 영역

   * 원본 제목
   * 출처
   * 원본 URL
   * 수집일
   * 카테고리
   * 썸네일
4. 강릉노트 초안 영역

   * 제목
   * 한 줄 요약
   * 카테고리
   * 대표 이미지
   * 출처 URL
   * 본문 초안
5. 버튼

   * 저장하기: disabled
   * 취소: `/admin/v2/inbox`로 이동
   * 다음 단계 안내: “저장 기능은 Phase 1-C2에서 구현 예정”

## 데이터 매핑 원칙

수집함 항목을 강릉노트 초안으로 보여줄 때는 아래 기준으로 매핑하세요.

| 수집함 데이터                | 강릉노트 초안              |
| ---------------------- | -------------------- |
| title                  | 제목                   |
| description            | 한 줄 요약 또는 본문 초안      |
| category               | 카테고리                 |
| thumbnail              | 대표 이미지               |
| source                 | 출처                   |
| link                   | 원본 URL               |
| crawledAt 또는 updatedAt | 수집일                  |
| contentBlocks가 있으면     | 본문 초안 미리보기           |
| contentBlocks가 없으면     | description 기반 본문 초안 |

이번 단계에서는 저장하지 않으므로 기존 데이터는 절대 변경되지 않아야 합니다.
