# Phase 1-C2 승인 범위

## 강릉노트 초안 저장 기능

이번 단계의 목표는 `/admin/v2/notes/new?sourceId=...` 화면에서 표시된 강릉노트 초안을 **기존 event 레코드에 초안 형태로 저장**하는 것입니다.

이번 단계는 “공개”가 아닙니다.
이번 단계는 “오늘의 강릉소식 선정”이 아닙니다.
이번 단계는 “SNS 발행”이 아닙니다.
이번 단계는 “광고 후보 등록”이 아닙니다.

오직 **강릉노트 초안 저장**까지만 구현합니다.

---

## 1. 허용 작업

다음 작업만 허용합니다.

1. `/admin/v2/notes/new?sourceId=...` 화면에서 초안 필드를 editable로 변경
2. 제목, 한 줄 요약, 카테고리, 대표 이미지, 출처, 원본 URL, 본문 초안 수정 가능하게 구성
3. 저장 버튼 활성화
4. 기존 `PATCH /api/events/:id` 또는 이미 존재하는 안전한 수정 API만 사용
5. 저장 대상은 새 레코드 생성이 아니라 기존 `sourceId` event 레코드
6. `contentBlocks`는 강릉노트 본문 초안으로 저장
7. 저장 후 status는 공개 상태로 바꾸지 말 것
8. 저장 후 홈에 노출하지 말 것
9. 저장 후 오늘의 강릉소식으로 자동 등록하지 말 것
10. 저장 성공 시 안내 toast 또는 메시지 표시
11. 저장 성공 후 `/admin/v2/notes/:id` 또는 현재 화면에 머무르기 중 하나를 선택해 보고
12. typecheck 실행
13. build 실행

---

## 2. 저장 시 상태 원칙

이번 단계에서 상태값을 `approved`, `published`, `active`로 바꾸면 안 됩니다.

기본 원칙:

* 기존 status가 `draft`이면 `draft` 유지
* 기존 status가 `pending`이면 `draft` 또는 기존 값 유지 방식을 보고 후 적용
* 공개 상태로 변경 금지
* 오늘의 강릉소식 자동 지정 금지
* SNS 발행 상태 변경 금지

추천:

```text
status는 변경하지 않는다.
```

만약 저장 API가 status 필드를 반드시 요구한다면, 기존 status를 그대로 다시 보내는 방식으로 처리하세요.

---

## 3. contentBlocks 저장 원칙

본문 초안은 `contentBlocks`에 저장합니다.

단, 이번 단계에서 BlockNote 전체 편집기를 무리하게 붙이지 않아도 됩니다.

우선 순위는 다음과 같습니다.

1. 기존 contentBlocks가 있으면 정규화해서 표시
2. contentBlocks가 없으면 description 기반으로 기본 paragraph block 생성
3. 저장 시에는 BlockNote 호환 가능한 기본 JSON 구조로 저장
4. 레거시 포맷을 새로 만들지 말 것
5. `normalizeBlockNoteContent` 로직이 필요하면 새 컴포넌트 내부 유틸로 분리할 것

이번 단계에서는 기존 `admin-event-detail.tsx`의 패치 코드를 가져와 억지로 붙이지 마세요.

## 5. UI 구성

`/admin/v2/notes/new?sourceId=...` 화면은 다음처럼 수정하세요.

### 원본 정보 영역

읽기 전용 유지:

1. 원본 제목
2. 출처
3. 원본 URL
4. 수집일
5. 원본 썸네일

### 강릉노트 초안 편집 영역

수정 가능:

1. 제목
2. 한 줄 요약
3. 카테고리
4. 대표 이미지 URL
5. 출처
6. 원본 URL
7. 본문 초안

### 버튼

1. 저장하기 — 활성화
2. 취소 — `/admin/v2/inbox` 이동
3. 저장 후 편집 계속 — 선택사항
4. 오늘의 강릉소식으로 선정 — 아직 만들지 말 것
5. SNS 발행 — 아직 만들지 말 것
